## Objective and decision boundary

Compare free or potentially free sources for a recording-centered graph. Measure correct recording resolution, usable typed facts at their actual scope, exclusive and combined contribution, latency, storage/retention, and integration effort across the same 500 recordings. Keep identity, credit, work rights, derivative relationships, context, and presentation data separate. Do not choose a primary source before results and developer review. Do not treat a missing record as a false fact or an album-wide credit as a recording credit.

## Gate 2: source eligibility and access

For each source/route, record terms URL, date checked, machine-access eligibility for research, public-app eligibility, attribution, raw-response retention, derived-claim retention, rate limits, credentials, and access outcome. Recheck current official documentation immediately before calls; the [capability audit](Source%20Capability%20Audit.md) is a 2026-10-10 desk review. Use `source-route-register.tsv` as the initial route inventory and expand it as needed. An unknown permission is `hold`, not permission to scrape.

Core automated research routes to assess first, subject to current terms and live availability: MusicBrainz API or dump, Discogs CC0 XML dump, Wikidata structured data, Open Opus, ListenBrainz mapper, DOREMUS, Library of Congress, Wikipedia/MediaWiki API, TheAudioDB free v1, VIAF, and AcousticBrainz historical dump/service if obtainable. These are **candidates**, not a requirement to issue 500 requests to each. Make route-specific eligibility explicit: Open Opus has a meaningful classical-work denominator; a mapper contributes recording identity but no credits; Wikipedia extraction has citation and scope review; Discogs API and dump have distinct rules. Spotify and AcoustID require provider ID or audio/fingerprint inputs and belong in an input-bridge/conditional identity track, not general credit scoring. Cover Art Archive is a presentation track. Manual/reference candidates such as IFPI ISRC, SoundExchange, Songview, society portals, WhoSampled, AllMusic, 45cat/45worlds, Afrodisc and Flat International can support permitted spot validation but should not be assigned zero automated coverage. MLC, SecondHandSongs, Last.fm, Genius and other gated routes stay on hold until their specific access and research/product terms are confirmed. CISAC paid third-party ISWC API is outside the free benchmark; assess its separate open-data mapping only if permitted.

Never submit private credentials to the repo. Keep downloads and responses out of git unless small and demonstrably redistributable. Record a blocked or inapplicable route explicitly so absence of measurements is not confused with zero coverage.

## Gate 3: query plan and pilot

For each eligible route, write an endpoint/dump plan before querying: input identifiers or title/artist fields, candidate search strategy, exact entity fetch, relationship expansions, maximum candidates and request budget per recording, rate/concurrency, retry policy, response retention, and how a `no match` is distinguished from an error or access block. Use the same frozen recording targets, but allow source-specific queries. Where a route supports ISRC, try the independently documented ISRC first; if it is unavailable or gives no adjudicated recording match, try title/artist plus version clues. Where the route cannot search by ISRC, use its best supported fallback and record that limitation. Do not feed a source an ID obtained exclusively from that same source as the only lookup path when measuring discovery; report `ISRC`, `title/artist`, other independent-ID, and crosswalk-assisted paths separately. Record all candidate matches, including rejected alternatives.

First run a small, explicitly labeled **engineering pilot** across every broad era and difficult cases to verify parsers, rights, latency, and rate limits. Pilot outputs may later be included only if the same frozen corpus/query protocol is applied and the pilot did not change membership based on source results. Fix parsers and query plans before the full run. Capture retrieval timestamps and dataset versions.

## Dataset contract

Use one research run directory outside tracked planning docs for large data, with a `run.json` manifest: UTC start/end, corpus SHA-256, git revision, operator, environment, route versions, query-plan versions, code version, and deviations. Suggested tables (CSV/Parquet/SQLite are implementation choices; the columns are the contract):

| Table | Required content |
| --- | --- |
| `eligibility` | route, role, access state, terms URL/date, permissions, retention/attribution restrictions, credentials needed, applicability rule and denominator |
| `query_log` | run, corpus ID, route, query ID/type/input, **lookup mode** (`isrc`, `title_artist`, `other_independent_id`, `crosswalk_assisted`), supplied ISRC/provider and independent evidence when used, start/end UTC, status, HTTP or parser error, retry/wait, bytes, response retained flag, payload pointer/hash if allowed |
| `candidates` | query ID, source entity ID/URL, source entity type/scope, raw name/version, match signals and rank, reviewed target match (`correct`, `wrong`, `ambiguous`, `unreviewed`) |
| `claims` | corpus ID, route, source entity ID, subject/target IDs and names, raw role/value, normalized family and qualifiers, **source scope** (`recording`, `track`, `work`, `release`, `artist`, etc.), evidence pointer, extraction confidence, review state |
| `attributes` | corpus ID, route, entity/scope, raw field, value/unit, source date, rights and nullable/missing distinction; cover descriptive values such as genre, release dates, language, mood, popularity, certification only when present |
| `review` | sampled claim IDs, independent evidence and citation, reviewer decision/reason, unresolved/conflict flag; include agreements, disagreements, single-source and version-error cases |

Keep raw response snapshots only if the route permits them. If not, keep permitted identifiers and metadata plus `response_received`, size, timing and restriction in the query log. Preserve raw labels even when a provisional normalized role is assigned. Never merge distinct work, recording, release and rights scopes merely because text labels look alike. The [provisional type map](Source%20Capability%20Audit.md#provisional-cross-source-semantic-type-map) is a comparison aid, not a final graph schema.

## Analysis to deliver

1. Per route and applicable stratum: number queried; correct, wrong, ambiguous and no recording matches; errors/access holds; observed claim counts by semantic family and source scope; unique targets and contributors; field presence/null rates. Include numerator and denominator. Report classical-only and audio-only routes on their eligible subset, not a misleading 500-item denominator.
2. Marginal lift and exclusive contribution by normalized `(subject identity, relationship family + qualifier, target identity, scope)` after match adjudication. Show pairwise overlap and several plausible combinations without assigning an arbitrary fixed primary-source order. Keep uncertain identity/normalization claims out of verified-lift totals, but report them separately.
3. Correctness audit of a stratified sample: independently cited decisions for single-source claims, agreements, conflicts, and likely version errors. Cross-source agreement is a review trigger, not proof. Report unresolved fraction and sample sizes; do not claim recall against an unknown universe of all real credits.
4. End-to-end wall time, requests, rate-limit wait, bytes/disk, useful validated claims per second, errors/retries, setup effort, query granularity, and maintenance/terms risks. Separate cold and cached/dump timings and disclose hardware/network conditions.
5. Side-channel value: non-graph fields actually returned (dates, formats, catalog IDs, genres, descriptors, popularity, artwork references) with usable coverage and rights; do not call certifications exact sales.
6. A recommendation matrix with evidence, tradeoffs and open decisions for the developer. Preserve dataset/query provenance so future questions can be answered without rerunning everything.
